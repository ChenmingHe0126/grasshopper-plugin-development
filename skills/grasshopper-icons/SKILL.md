# Grasshopper Icons

Create icons that communicate component behavior at actual toolbar size. Read the component's inputs, transformation, and outputs before choosing a motif. Treat component names and subcategories as context; a shared noun alone does not describe an operation.

## Choose the work

- For a new family, establish semantics and visual rules using [design-workflow.md](references/design-workflow.md).
- For a refinement, inspect existing assets and actual 24-pixel outputs before changing geometry or palette. Read [case-notes.md](references/case-notes.md) for lessons from engineering and scanned-tree icon work.
- To export independent PNGs or a sprite sheet, read [tooling.md](references/tooling.md) and use `scripts/icon_tools.py`.
- To connect approved assets to components, inspect the repository's resource conventions and read [resource-integration.md](references/resource-integration.md).

## Working rules

1. Agree the semantic distinction among related components. Show input → operation → output when that distinction matters; do not replace a transformation with two copies of its output.
2. Keep one family language: outline, perspective, geometry, palette roles, action direction, and optical size. Retain selected design choices when the user asks for refinement.
3. Choose production deliberately. Use available image-generation tools when suitable and authorized; use original vector or code drawing when precise geometry, existing editable assets, or pixel control makes that preferable. Inspect any tool's save behavior against the current task's permissions. A previous task's destination restriction is not a blanket ban on generation.
4. State production provenance accurately: image-generated, code-drawn, mixed, or provided. Name the tool and the model only when known. If generation is unavailable or fails, report that plainly before using an authorized alternative. Do not imply that a code-rendered icon was generated by an image model.
5. Preserve real alpha. Never remove a white background by treating all white pixels as transparent: pale or ice-white engineering faces may be intentional.
6. Export a large master and an exact 24×24 PNG. Inspect the actual-size icons on light and dark backgrounds, plus an 8× nearest-neighbor view. A beautiful master does not establish toolbar legibility.
7. Keep names and outputs inside the authorized scope. Preserve existing files unless replacement is requested; create versioned variants when appropriate. Resource integration, builds, commits, and publishing follow the task's authorization.

## Finish

Verify sizes, nonempty alpha, transparent edges, and the family at 24 pixels. Report exact saved paths, production method, validation, and any failures or limits. Deliver preview sheets as review aids, separate from toolbar resources. Do not report a Rhino/Grasshopper runtime check unless it was actually performed.
